Em resumo

O skillmanager3x é um conjunto de skills (instruções prontas em arquivos de texto) para quem usa o Claude Code e trabalha em sessões longas. Elas resolvem o problema de perder o fio quando a conversa enche: o session-handoff grava o estado num arquivo, você limpa com /clear e o prime retoma lendo esse arquivo. Há ainda um checkpoint rápido, uma auditoria da memória e uma barra de status. Para usar, basta copiar as pastas para ~/.claude/skills.

O que é

Uma biblioteca de gestão de sessão — não um framework

Não há build, dependências nem código executável. Cada skill é uma pasta com um SKILL.md (markdown + frontmatter YAML) que o Claude Code carrega quando você fala um dos gatilhos.

🤝 session-handoff

Passa o bastão antes do /clear ou da troca de agente. Mostra no chat e grava em handoffs/history/<UTC>.md + handoffs/latest.md, com próxima ação exata, verificação real e checagem de segredos.

🔎 prime

O par do handoff: no início da sessão lê CLAUDE.md/AGENTS.md, context/, tasks/ e handoffs/latest.md e devolve um briefing curto. Só lê; não retoma deploy nem envio sozinho.

📊 session-statusline

Checkpoint rápido durante o trabalho: foco atual, o que foi pra memória, decisões recentes, próximos passos e uma recomendação (continuar, compactar, auditar, handoff ou limpar).

🧹 memory-audit

Inventário do que está em ~/.claude/projects/<projeto>/memory/ e no CLAUDE.md. Separa fato durável (mantém) de estado de curto prazo (descarta) e ruído (remove).

Como funciona

Gatilhos que não se sobrepõem

Regra de bolso: fim de sessão → handoff. "Como estamos?" → statusline. "O que tem na memória?" → audit. Você fala em linguagem natural, o harness casa com a description do frontmatter e carrega a skill certa.

Você fala o gatilho→ Claude Code casa a description→ Carrega o SKILL.md→ Segue o formato de saída→ Responde no chat (o handoff também grava)

🤝 Gatilhos do handoff

"handoff", "vou dar /clear", "encerrar sessão", "passar para outro agente", "wrap up", "resumo final antes de limpar".

🔎 Gatilhos do prime

"prime", "retoma", "continua de onde parou", "lê o handoff", ou ao entrar num projeto com handoffs/latest.md.

📊 Gatilhos da statusline

"statusline", "checkpoint", "onde estamos", "como está a sessão", "próximos passos", "organiza/otimiza a sessão".

🧹 Gatilhos do audit

"analise a memória", "analise CLAUDE.md", "o que foi guardado", "memória inchada", "limpa memória".

Em destaque · troca de sessão

Trocar de sessão sem perder o fio: handoff → /clear → /prime

Quando o contexto enche ou a sessão já compactou, não insista na mesma conversa. Grave o estado num arquivo, limpe e recomece lendo esse arquivo. É o processo que recomendamos para qualquer trabalho longo, no Claude Code e no Codex.

/session-handoff (grava)→ /clear (zera a conversa)→ /prime (relê e resume)→ Continua da próxima ação

💾 1. /session-handoff

Escreve o que foi feito, o que está em andamento, a próxima ação exata e o que depende do humano, sem segredos. Grava um arquivo novo em handoffs/history/<data-UTC>.md (nunca sobrescreve) e atualiza handoffs/latest.md.

🧹 2. /clear

Começa do zero: contexto vazio, sem o peso das compactações. Nada se perde, porque o estado está no arquivo. No Codex, abra uma sessão nova.

🔎 3. /prime

Antes de agir, lê AGENTS.md/CLAUDE.md, context/, tasks/current.md e handoffs/latest.md e devolve um briefing curto: objetivo, regra principal com fonte, última decisão, próxima ação e conflitos. Só lê: não retoma publicação, deploy ou envio por conta própria.

⚠️ Existem duas session-handoff: confira qual você tem

Versão antiga (só chat), a que este repositório trazia até out/2026 e que circula em outros kits: mostra o resumo na conversa e não grava nada. Ao dar /clear, o resumo vai embora junto, a menos que você copie à mão, e o /prime não encontra o que ler.

Versão atual (grava em arquivo), a que está agora em skill/pt e skill/en, igual à do kit agente-claude-codex 1.4.2: mostra no chat e grava em handoffs/ pelo script handoff-grava.py, com o latest.md como índice dos trabalhos abertos (o mesmo formato que o hook do Execução Longa lê); cria a pasta se o projeto só tiver CLAUDE.md.

# 0 = versão só chat; 1 ou mais = grava em handoffs/
grep -c "handoffs/history" ~/.claude/skills/session-handoff/SKILL.md

# trocar pela versão que grava (e instalar o par prime)
cp -r skill/pt/session-handoff skill/pt/prime ~/.claude/skills/

⏳ Para trabalho de horas: Execução Longa

Este ciclo é a base do projeto Execução Longa, o método para agentes que trabalham horas ou dias (/goal, arquivos de estado, tetos e critério de pronto). Lá está o hook que mede o contexto e grava o handoff sozinho em ~70% e ~85% e logo depois de uma compactação, enquanto o cache ainda está quente; você só dá /clear e /prime. Também estão a pesquisa por trás das faixas de contexto e o recall para buscar em tudo o que já foi dito.

Pré-requisitos

Basicamente nada

Se você já usa o Claude Code, está pronto. Não há instalação de pacote, runtime nem serviço no ar.

Claude Code

O CLI da Anthropic, com suporte a skills (pasta skills/ varrida no start).

# conferir que está instalado
claude --version

O repositório

Clone (ou baixe) — as skills são só arquivos de texto.

git clone https://github.com/inematds/skillmanager3x
cd skillmanager3x

Uma pasta de skills

Global (todas as sessões) ou por projeto. Crie se não existir.

# global
mkdir -p ~/.claude/skills
Guia de uso · passo a passo

Do clone ao primeiro handoff

Cinco passos. O mais longo leva um minuto.

1

Clone o repositório

As skills vivem em skill/pt/ e skill/en/ — mesma estrutura nos dois idiomas.

git clone https://github.com/inematds/skillmanager3x
cd skillmanager3x
2

Escolha o idioma

Os campos name e description ficam em inglês nas duas versões (pra triggering consistente do harness), mas a description de pt/ inclui gatilhos em português.

ls skill/pt   # session-handoff  prime  session-statusline  memory-audit
ls skill/en   # mesma estrutura, textos em inglês
3

Instale as skills

Copie a pasta inteira de cada skill — com o SKILL.md dentro. Não achate a estrutura.

# global — vale em todas as sessões
mkdir -p ~/.claude/skills
cp -r skill/pt/session-handoff    ~/.claude/skills/
cp -r skill/pt/prime              ~/.claude/skills/
cp -r skill/pt/session-statusline ~/.claude/skills/
cp -r skill/pt/memory-audit       ~/.claude/skills/

# ou por projeto
cp -r skill/pt/session-handoff <projeto>/.claude/skills/
4

Verifique que registrou

No Claude Code, liste as skills disponíveis. As quatro devem aparecer.

/skills   # session-handoff · prime · session-statusline · memory-audit
5

Use pelo gatilho, não pelo nome

Você não precisa decorar comandos — fale naturalmente e a skill certa entra.

# fim de sessão: grava handoffs/latest.md, depois /clear
vou dar /clear, faz handoff antes

# sessão nova: lê o handoff e resume
/prime

# no meio do trabalho
statusline

# revisar memória
analise a memória do projeto, tá bagunçada
Exemplos

Como é a saída de verdade

Três formatos, três propósitos. Tudo sai no chat; só o handoff também grava em handoffs/, que é de onde o prime lê.

🤝 Handoff — refatoração de auth

Gravado em handoffs/history/2026-10-13T014500Z.md e copiado para handoffs/latest.md.

# Handoff — 2026-10-13 — refatoração do middleware de auth

## Estado aceito
- [confirmed] auth/jwt_validator.py extraído de middleware.py:45-180

## Proposto / tentado, não confirmado
- [unverified] cache de chaves públicas TTL 5min — sem teste
- [?] migração v1→v2 — usuário queria revisar antes

## Verificação
- Rodado: `pytest tests/auth` → 12 passed

## Estado em execução
- Processos em segundo plano: shell_a3f → pytest --watch

## Próxima ação exata
Revisar se a migração v1→v2 entra agora (precisa do ok do usuário).

📊 Statusline — checkpoint

Termina sempre com uma Recomendação: qual skill (ou nenhuma) faz sentido em seguida.

# Statusline

## Estado
- Foco atual: ajustar paginação do endpoint /users
- Contexto: moderado
- Risco: sem teste de carga com >10k registros

## O que ficou guardado na memória
- Guardado confirmado: none
- Candidatos: prefere keyset sobre offset

## Próximos passos
1. Rodar teste com 50k registros
2. Atualizar OpenAPI schema

## Recomendação
continuar

🧹 Memory audit — inventário

A saída é recomendação, não execução. Se quiser aplicar os cortes, peça numa segunda etapa: "ok, aplica isso".

# Memory Audit

## Manter (fatos duráveis)
- user_role.md → user é eng. backend Go, novo em React
- feedback_testing.md → testes de integração no Postgres real (incidente Q3/2025)

## Considerar mover pro CLAUDE.md
- project_auth_rewrite.md → motivação (compliance) — vale na doc do projeto

## Remover (curto prazo / ruído)
- session_2026-04-15.md → estado de sessão antiga
- bug_fix_recipe_xyz.md → fix já aplicado, código fala por si

Bônus · statusline-cmd

A barra que te diz onde você está — e quanto sobrou

Fora as três skills, o repo traz uma statusline pro Claude Code: a linha fixa abaixo do input, com diretório, modelo, esforço, contexto restante e quanto do seu limite já foi embora. Um comando pra instalar.

# o que aparece no terminal
nei@maquina:~/projetos/wifi Opus 5/low ctx 10% 5h:24%→00:10 w:29%→10/08 21:00 d:109.6M

🧭 Onde e com quê

user@host:cwd mais Opus 5/low — o modelo e o nível de esforço da sessão, acompanhando o que você escolheu no /model.

🪟 Quanto de contexto

ctx 10% — o quanto da janela já foi usado. É o número que diz se dá pra continuar ou se está na hora de um handoff.

⏳ Quanto de limite

5h:24%→00:10 e w:29%→10/08 21:00 — uso e horário de reset das janelas de 5 horas e semanal. d:109.6M são os tokens do dia.

1

Instale com um comando

O script copia a statusline para ~/.claude/ e registra o bloco statusLine no seu settings.json — preservando o resto do arquivo, com backup .bak.

git clone https://github.com/inematds/skillmanager3x
bash skillmanager3x/statusline-cmd/install.sh
2

Confira a prévia

O instalador imprime a linha já montada com os seus dados. Ela aparece no próximo render do Claude Code — nenhuma sessão precisa ser reiniciada.

# dependências, se faltar alguma
sudo apt install jq curl python3
3

Se quiser tirar

O desinstalador remove só a chave statusLine do settings.json; o resto das suas configurações fica intacto.

bash statusline-cmd/install.sh --uninstall

Os percentuais de 5h e semana vêm do endpoint de uso da Anthropic usando as suas próprias credenciais (~/.claude/.credentials.json) — nenhum token vai no repositório. Detalhes, campos disponíveis e como personalizar: statusline-cmd/README.md.

Nomes parecidos, coisas diferentes: a skill session-statusline escreve um checkpoint em texto quando você pede; a pasta statusline-cmd instala a barra fixa do terminal.
