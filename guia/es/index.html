En resumen

skillmanager3x es un conjunto de skills (instrucciones listas en archivos de texto) para quienes usan Claude Code y trabajan en sesiones largas. Resuelven el problema de perder el hilo cuando la conversación se llena: session-handoff guarda el estado en un archivo, tú limpias con /clear y prime retoma leyendo ese archivo. Además hay un checkpoint rápido, una auditoría de la memoria y una barra de estado. Para usarlas, basta copiar las carpetas a ~/.claude/skills.

Qué es

Una biblioteca de gestión de sesión — no un framework

No hay build, dependencias ni código ejecutable. Cada skill es una carpeta con un SKILL.md (markdown + frontmatter YAML) que Claude Code carga cuando dices uno de los gatillos.

🤝 session-handoff

Pasa la posta antes del /clear o del cambio de agente. Muestra en el chat y guarda en handoffs/history/<UTC>.md + handoffs/latest.md, con la próxima acción exacta, verificación real y revisión de secretos.

🔎 prime

El par del handoff: al inicio de la sesión lee CLAUDE.md/AGENTS.md, context/, tasks/ y handoffs/latest.md y devuelve un briefing corto. Solo lee; no retoma deploys ni envíos por su cuenta.

📊 session-statusline

Checkpoint rápido durante el trabajo: foco actual, qué fue a la memoria, decisiones recientes, próximos pasos y una recomendación (continuar, compactar, auditar, handoff o limpiar).

🧹 memory-audit

Inventario de lo que hay en ~/.claude/projects/<proyecto>/memory/ y en CLAUDE.md. Separa el hecho duradero (se mantiene) del estado de corto plazo (se descarta) y del ruido (se elimina).

Cómo funciona

Gatillos que no se superponen

Regla de bolsillo: fin de sesión → handoff. "¿Cómo vamos?" → statusline. "¿Qué hay en la memoria?" → audit. Hablas en lenguaje natural, el harness lo compara con la description del frontmatter y carga la skill correcta.

Dices el gatillo→ Claude Code compara la description→ Carga el SKILL.md→ Sigue el formato de salida→ Responde en el chat (el handoff además guarda)

🤝 Gatillos del handoff

"handoff", "vou dar /clear", "encerrar sessão", "passar para outro agente", "wrap up", "resumo final antes de limpar".

🔎 Gatillos del prime

"prime", "retoma", "continua de onde parou", "lê o handoff", o al entrar en un proyecto con handoffs/latest.md.

📊 Gatillos de la statusline

"statusline", "checkpoint", "onde estamos", "como está a sessão", "próximos passos", "organiza/otimiza a sessão".

🧹 Gatillos del audit

"analise a memória", "analise CLAUDE.md", "o que foi guardado", "memória inchada", "limpa memória".

Destacado · cambio de sesión

Cambiar de sesión sin perder el hilo: handoff → /clear → /prime

Cuando el contexto se llena o la sesión ya se compactó, no insistas con la misma conversación. Guarda el estado en un archivo, limpia y empieza de nuevo leyendo ese archivo. Es el proceso que recomendamos para cualquier trabajo largo, en Claude Code y en Codex.

/session-handoff (guarda)→ /clear (reinicia la conversación)→ /prime (relee y resume)→ Continúa desde la próxima acción

💾 1. /session-handoff

Escribe lo que se hizo, lo que está en curso, la próxima acción exacta y lo que depende del humano, sin secretos. Guarda un archivo nuevo en handoffs/history/<fecha-UTC>.md (nunca sobrescribe) y actualiza handoffs/latest.md.

🧹 2. /clear

Empieza de cero: contexto vacío, sin el peso de las compactaciones. No se pierde nada, porque el estado está en el archivo. En Codex, abre una sesión nueva.

🔎 3. /prime

Antes de actuar, lee AGENTS.md/CLAUDE.md, context/, tasks/current.md y handoffs/latest.md y devuelve un briefing corto: objetivo, regla principal con fuente, última decisión, próxima acción y conflictos. Solo lee: no retoma publicaciones, deploys ni envíos por su cuenta.

⚠️ Existen dos session-handoff: revisa cuál tienes

Versión antigua (solo chat), la que este repositorio traía hasta oct/2026 y que circula en otros kits: muestra el resumen en la conversación y no guarda nada. Al dar /clear, el resumen se va junto, a menos que lo copies a mano, y /prime no encuentra qué leer.

Versión actual (guarda en archivo), la que está ahora en skill/pt y skill/en, igual a la del kit agente-claude-codex 1.5.2: muestra en el chat y guarda en handoffs/ mediante el script handoff-grava.py, con latest.md como índice de los trabajos abiertos (el mismo formato que lee el hook de Ejecución Larga); crea la carpeta si el proyecto solo tiene CLAUDE.md.

# 0 = versión solo chat; 1 o más = guarda en handoffs/
grep -c "handoffs/history" ~/.claude/skills/session-handoff/SKILL.md

# cambiar por la versión que guarda (e instalar el par prime)
cp -r skill/pt/session-handoff skill/pt/prime ~/.claude/skills/

⏳ Para trabajo de horas: Ejecución Larga

Este ciclo es la base del proyecto Ejecución Larga, el método para agentes que trabajan horas o días (/goal, archivos de estado, límites y criterio de listo). Allí está el hook que mide el contexto y guarda el handoff solo en ~70% y ~85% y justo después de una compactación, mientras el caché aún está caliente; tú solo das /clear y /prime. También están la investigación detrás de las franjas de contexto y el recall para buscar en todo lo que ya se ha dicho.

Requisitos

Básicamente nada

Si ya usas Claude Code, estás listo. No hay instalación de paquetes, runtime ni servicio en línea.

Claude Code

El CLI de Anthropic, con soporte de skills (la carpeta skills/ se recorre al iniciar).

# verificar que está instalado
claude --version

El repositorio

Clónalo (o descárgalo) — las skills son solo archivos de texto.

git clone https://github.com/inematds/skillmanager3x
cd skillmanager3x

Una carpeta de skills

Global (todas las sesiones) o por proyecto. Créala si no existe.

# global
mkdir -p ~/.claude/skills
Guía de uso · paso a paso

Del clon al primer handoff

Cinco pasos. El más largo toma un minuto.

1

Clona el repositorio

Las skills viven en skill/pt/ y skill/en/ — misma estructura en los dos idiomas.

git clone https://github.com/inematds/skillmanager3x
cd skillmanager3x
2

Elige el idioma

No hay versión en español de las skills: usa skill/pt o skill/en. Los campos name y description quedan en inglés en las dos versiones (para un triggering consistente del harness), pero la description de pt/ incluye gatillos en portugués. Puedes seguir hablando en español: el agente entiende la intención.

ls skill/pt   # session-handoff  prime  session-statusline  memory-audit
ls skill/en   # misma estructura, textos en inglés
3

Instala las skills

Copia la carpeta completa de cada skill — con el SKILL.md dentro. No aplanes la estructura.

# global — vale en todas las sesiones
mkdir -p ~/.claude/skills
cp -r skill/pt/session-handoff    ~/.claude/skills/
cp -r skill/pt/prime              ~/.claude/skills/
cp -r skill/pt/session-statusline ~/.claude/skills/
cp -r skill/pt/memory-audit       ~/.claude/skills/

# o por proyecto
cp -r skill/pt/session-handoff <proyecto>/.claude/skills/
4

Verifica que se registraron

En Claude Code, lista las skills disponibles. Las cuatro deben aparecer.

/skills   # session-handoff · prime · session-statusline · memory-audit
5

Usa el gatillo, no el nombre

No necesitas memorizar comandos — habla de forma natural y entra la skill correcta.

# fin de sesión: guarda handoffs/latest.md, después /clear
voy a hacer /clear, haz el handoff antes

# sesión nueva: lee el handoff y resume
/prime

# en medio del trabajo
statusline

# revisar la memoria
analiza la memoria del proyecto, está desordenada
Ejemplos

Cómo es la salida de verdad

Tres formatos, tres propósitos. Todo sale en el chat; solo el handoff además guarda en handoffs/, de donde lee prime.

🤝 Handoff — refactorización de auth

Guardado en handoffs/history/2026-10-13T014500Z.md y copiado a handoffs/latest.md.

# Handoff — 2026-10-13 — refactorización del middleware de auth

## Estado aceptado
- [confirmed] auth/jwt_validator.py extraído de middleware.py:45-180

## Propuesto / intentado, no confirmado
- [unverified] caché de claves públicas TTL 5min — sin prueba
- [?] migración v1→v2 — el usuario quería revisar antes

## Verificación
- Ejecutado: `pytest tests/auth` → 12 passed

## Estado en ejecución
- Procesos en segundo plano: shell_a3f → pytest --watch

## Próxima acción exacta
Revisar si la migración v1→v2 entra ahora (necesita el ok del usuario).

📊 Statusline — checkpoint

Termina siempre con una Recomendación: qué skill (o ninguna) tiene sentido a continuación.

# Statusline

## Estado
- Foco actual: ajustar paginación del endpoint /users
- Contexto: moderado
- Riesgo: sin prueba de carga con >10k registros

## Qué quedó guardado en la memoria
- Guardado confirmado: none
- Candidatos: prefiere keyset sobre offset

## Próximos pasos
1. Ejecutar prueba con 50k registros
2. Actualizar OpenAPI schema

## Recomendación
continuar

🧹 Memory audit — inventario

La salida es recomendación, no ejecución. Si quieres aplicar los cortes, pídelo en una segunda etapa: "ok, aplica eso".

# Memory Audit

## Mantener (hechos duraderos)
- user_role.md → el usuario es ing. backend Go, nuevo en React
- feedback_testing.md → pruebas de integración en Postgres real (incidente Q3/2025)

## Considerar mover a CLAUDE.md
- project_auth_rewrite.md → motivación (compliance) — vale en la doc del proyecto

## Eliminar (corto plazo / ruido)
- session_2026-04-15.md → estado de sesión antigua
- bug_fix_recipe_xyz.md → fix ya aplicado, el código habla por sí solo

## Puntos de atención
- Duplicación: feedback_pr_size.md y feedback_review_style.md
- Obsoleto: reference_grafana.md apunta a un dashboard que cambió de URL
Bonus · statusline-cmd

La barra que te dice dónde estás — y cuánto queda

Además de las tres skills, el repo trae una statusline para Claude Code: la línea fija bajo el input, con directorio, modelo, esfuerzo, contexto restante y cuánto de tu límite ya se fue. Un comando para instalar.

# lo que aparece en la terminal
nei@maquina:~/projetos/wifi Opus 5/low ctx 10% 5h:24%→00:10 w:29%→10/08 21:00 d:109.6M

🧭 Dónde y con qué

user@host:cwd más Opus 5/low — el modelo y el nivel de esfuerzo de la sesión, siguiendo lo que elegiste en /model.

🪟 Cuánto contexto

ctx 10% — cuánto de la ventana ya se usó. Es el número que dice si se puede continuar o si es hora de un handoff.

⏳ Cuánto límite

5h:24%→00:10 y w:29%→10/08 21:00 — uso y hora de reinicio de las ventanas de 5 horas y semanal. d:109.6M son los tokens del día.

1

Instala con un comando

El script copia la statusline a ~/.claude/ y registra el bloque statusLine en tu settings.json — preservando el resto del archivo, con backup .bak.

git clone https://github.com/inematds/skillmanager3x
bash skillmanager3x/statusline-cmd/install.sh
2

Revisa la vista previa

El instalador imprime la línea ya armada con tus datos. Aparece en el próximo render de Claude Code — no hace falta reiniciar ninguna sesión.

# dependencias, si falta alguna
sudo apt install jq curl python3
3

Si quieres quitarla

El desinstalador elimina solo la clave statusLine del settings.json; el resto de tus configuraciones queda intacto.

bash statusline-cmd/install.sh --uninstall

Los porcentajes de 5h y semana vienen del endpoint de uso de Anthropic usando tus propias credenciales (~/.claude/.credentials.json) — ningún token va en el repositorio. Detalles, campos disponibles y cómo personalizar: statusline-cmd/README.md (en portugués).

Nombres parecidos, cosas distintas: la skill session-statusline escribe un checkpoint en texto cuando lo pides; la carpeta statusline-cmd instala la barra fija de la terminal.

Roadmap

Dónde está y hacia dónde va

El proyecto es pequeño a propósito: skills disjuntas, sin superposición de gatillos.

Hecho
Las tres skills, en PT y ENsession-handoff, session-statusline y memory-audit, con SKILL.md completo en los dos idiomas y READMEs detallados en skill/en/ y skill/pt/ que cubren las decisiones de diseño.
Hecho
Gatillos sin superposiciónCada skill tiene un solo trabajo. La statusline termina con una recomendación que apunta a la siguiente — el enrutamiento es explícito, no adivinado.
Convención
Sincronizar en/pt al editarLas dos versiones tienen la misma estructura. Al tocar una skill, actualiza las dos — es la regla de mantenimiento del repo.
